# Surrey Snow Intelligence: put the property in the request

![PlowWow mascot Wow introduces a Surrey property request with address, shared paths and access priorities](/blog-images/surrey-snow-intelligence-property-request.jpg "Surrey property request with PlowWow")

**By the PlowWow team · October 26, 2026 · App features and city use cases**

A Surrey snow-service enquiry can start with one address. A useful property plan needs the next layer: which entrance, which connecting path, whose shared area and what the crew needs to know before arriving. Our current online flow helps carry an address and starting estimate into an optional request. The property review still does the work of defining the service.

This is a practical guide to that handoff, using Surrey property-management examples. It is not an announcement that every Snow Intelligence module is available across the city.

## The feature you can use now: carry the estimate forward

Open [PlowWow’s address estimator](/quote) and enter a complete street address and city. The public calculator finds the address with Google Maps and displays a standard residential starting estimate. You can see that estimate without supplying a name or email.

If you want a review, choose **“Follow up on this estimate.”** The next screen carries the address, starting figure and scope notes into the quote-request process. Review those details and add the information needed for the actual property. The follow-up is optional; seeing the number does not book a crew.

The map locates the address. It does not establish property boundaries, recognise every ramp or decide which surfaces belong in your service agreement. A commercial or strata address still needs a tailored review, even if the calculator displays its standard residential example.

## A Surrey example: one street address, several service areas

Consider a hypothetical Surrey property with a front entrance, a rear delivery door and a pedestrian connection to shared parking. The single street address identifies the site, but it does not tell us whether all three areas are included. The delivery door may need hand work while the parking route needs different equipment.

In the request notes, describe the connecting route rather than only the building. Explain where a visitor starts, which entrance they need and which steps or gates interrupt the route. If part of the property is maintained by another party, identify the boundary for review. These are planning examples, not claims about a named customer's site.

| Put this in the request | What the review needs to establish |
| --- | --- |
| Front entrance and path to shared parking | The actual clearing and treatment boundary |
| Rear delivery access and usual delivery period | How service and access can be coordinated |
| Gate, ramp or narrow passage | Equipment access and any separate hand work |
| Proposed snow-storage area | Whether it is suitable for the agreed operation |
| Council or manager contact | Who receives questions and authorises changes |

Keep private entry codes and residents' personal details out of general notes. Arrange any necessary access information directly with PlowWow.

## Road conditions and private-site service are separate questions

A municipal road update does not confirm that a private entrance, parking area or shared walkway has been serviced. Keep your request focused on the private areas you want included. Ask separately how public frontage, site access and private clearing boundaries are handled in the proposal.

For municipal information, start with the [City of Surrey](https://www.surrey.ca/) and its current snow and ice information. This article does not set a municipal deadline or represent a city service. For PlowWow's local enquiry route, use our [Surrey service page](/surrey).

## Ask for a useful beta workflow, then confirm access

Snow Intelligence is a first-year beta. The public estimator and optional quote handoff are the current starting point covered here. Client views, arrival notifications, photographs and visit-record access must be confirmed for the individual property.

For the hypothetical shared-access site, a useful question is: “Can our manager see what work was recorded and flag an unresolved access problem?” That is a requirement to discuss, not a promise that an automated alert or live service log is enabled. Read the [current beta status](/intelligence) before relying on a previewed feature.

## Finish with a reviewed scope

Before accepting a proposal, confirm included areas, treatment arrangements, service triggers, timing, available route capacity and how additional work is approved. An estimate, a submitted request and an accepted service agreement are different stages.
